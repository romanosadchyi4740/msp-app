# Інструкція користувача програмного забезпечення

Цей документ є інструкцією з розгортання та використання програмного забезпечення "Музична соціальна мережа". Документ призначений для адміністраторів системи та кінцевих користувачів.

## 1. Компоненти програмного забезпечення

Програмне забезпечення побудоване за клієнт-серверною архітектурою та складається з наступних ключових компонентів:

* **Серверна частина (Базовий рівень):** Розроблена мовою програмування Java з використанням платформи Spring Boot. Відповідає за обробку бізнес-логіки, маршрутизацію повідомлень у реальному часі (через протокол WebSocket) та криптографічний захист даних.
* **Клієнтська частина (Рівень представлення):** Реалізована за допомогою бібліотеки React. Забезпечує взаємодію з користувачем через графічний інтерфейс, виконаний у стилістиці наукової фантастики.
* **Система керування базами даних (СКБД):** Використовується об'єктно-реляційна СКБД PostgreSQL для надійного збереження структурованої інформації (облікових записів, зв'язків, метаданих).
* **Сховище об'єктів:** Інтегровано систему MinIO (сумісну з протоколом S3) для збереження та віддачі фізичних медіафайлів (аудіозаписів та зображень обкладинок).

## 2. Встановлення програмного забезпечення

Для успішного локального розгортання системи необхідно виконати наступну послідовність дій.

**Попередні вимоги:** 
На робочій станції мають бути встановлені: Java Development Kit (JDK), Node.js, інструмент керування пакунками (npm) та середовище контейнеризації Docker.

**Крок 1. Підготовка інфраструктури:**
1. Відкрийте кореневий каталог проєкту.
2. Запустіть інфраструктурні компоненти (PostgreSQL та MinIO) за допомогою Docker, виконавши команду в терміналі:
   ```bash
   docker-compose up -d
   ```

**Крок 2. Запуск серверної частини:**
1. Перейдіть до каталогу `backend`.
2. Виконайте збирання та запуск сервера за допомогою вбудованого засобу керування (Maven Wrapper):
   ```bash
   ./mvnw spring-boot:run
   ```
   *Примітка: Під час першого запуску система автоматично застосує міграції бази даних та створить необхідну структуру таблиць.*

**Крок 3. Запуск клієнтської частини:**
1. Перейдіть до каталогу `frontend`.
2. Встановіть необхідні бібліотеки залежностей:
   ```bash
   npm install
   ```
3. Запустіть локальний сервер розробки:
   ```bash
   npm run dev
   ```
4. Відкрийте веб-оглядач (браузер) за адресою, яку вкаже термінал (зазвичай `http://localhost:5173`).

**Альтернатива: запуск усієї системи в Docker.** Замість кроків 2–3 можна зібрати та запустити всі компоненти (PostgreSQL, MinIO, серверну та клієнтську частини, а також TURN-сервер coturn для тестування WebRTC) однією командою з кореневого каталогу проєкту:
```bash
docker compose --profile full up -d --build
```
Після запуску застосунок доступний за адресою `http://localhost:5173`, серверний інтерфейс — `http://localhost:8080`. Перед цим зупиніть локальний сервер розробки (`npm run dev`), оскільки він використовує той самий порт, або задайте інший порт змінною `FRONTEND_PORT`.

## 3. Налаштування програмного забезпечення

Для належного функціонування системи в різних середовищах (розробка, тестування, промислова експлуатація) передбачено механізм конфігурації за допомогою змінних оточення (Environment Variables). 

Основні конфігураційні параметри для серверної частини задаються у файлі конфігурації (наприклад, `application.yaml`) або передаються під час запуску:

* **Параметри бази даних:** Налаштування підключення до СКБД PostgreSQL (адреса сервера, порт, назва бази даних, ім'я користувача та пароль доступу).
* **Параметри сховища об'єктів (MinIO):** Облікові дані для доступу до сервісу (URL-адреса доступу, ключі доступу `access-key` та `secret-key`), а також назва цільового контейнера (bucket) для зберігання медіафайлів.
* **Криптографічні налаштування:** Секретні ключі, необхідні для роботи алгоритмів шифрування (наприклад, для захисту персональних повідомлень) та генерації токенів доступу (JWT). Ключі мають бути криптографічно стійкими та зберігатися у безпечному місці.
* **Інтеграція із зовнішніми сервісами:** Налаштування для роботи модуля авторизації через сторонні системи (наприклад, ідентифікатор клієнта Google OAuth2).

Серверна частина має два профілі Spring:

* **`local`** (типовий, вмикається автоматично) — значення за замовчуванням відповідають `docker-compose.yml`, тому локальний запуск не потребує жодних налаштувань.
* **`prod`** (вмикається змінною `SPRING_PROFILES_ACTIVE=prod`) — значень за замовчуванням немає; якщо хоча б одна змінна відсутня, сервер не запуститься.

Змінні оточення серверної частини: `DB_DATASOURCE_URL`, `DB_USERNAME`, `DB_PASSWORD`, `MINIO_URL`, `MINIO_PUBLIC_URL` (необов'язкова; адреса MinIO для посилань, що відкриває браузер, за замовчуванням дорівнює `MINIO_URL`), `MINIO_REGION`, `MINIO_USER`, `MINIO_PASSWORD`, `MINIO_BUCKET_NAME`, `JWT_SECRET`, `JWT_EXPIRATION` (необов'язкова), `ENCRYPTION_SECRET`, `GOOGLE_CLIENT_ID`, `CORS_ALLOWED_ORIGINS` (список адрес клієнтської частини через кому), `DATA_SEEDER_ENABLED` (`true`/`false`; лише для профілю `local` — створення демонстраційного користувача `artist@example.com`. Довідникові дані, як-от жанри, створюються в будь-якому профілі).

Для перевірки стану сервера (наприклад, балансувальником навантаження) доступна адреса `GET /actuator/health`, яка не потребує автентифікації й повертає лише загальний статус.

Для клієнтської частини адреси серверного інтерфейсу задаються змінними оточення під час збирання: `VITE_API_URL`, `VITE_WS_URL` (необов'язкова, за замовчуванням `${VITE_API_URL}/ws`) та `VITE_GOOGLE_CLIENT_ID`. Значення для локальної розробки містить файл `frontend/.env.development`; для збирання під інший домен скопіюйте `frontend/.env.example` у `frontend/.env.production.local` і вкажіть потрібні значення (або передайте їх як змінні оточення).

## 4. Базові функції програмного забезпечення

Після успішного розгортання та авторизації, користувачеві доступні наступні можливості:

* **Керування обліковим записом:** Реєстрація, проходження авторизації (зокрема через зовнішні сервіси, такі як Google), редагування профілю та можливість безповоротного видалення персональних даних ("Право на забуття").
* **Робота з музичними творами:** Завантаження аудіофайлів (доступно для користувачів зі статусом "Артист") із вбудованою системою запобігання дублюванню. Відтворення композицій через глобальний програвач.
* **Організація списків відтворення (Плейлистів):**
  * Створення публічних та приватних колекцій.
  * Створення "відгалужень" (копіювання) публічних колекцій інших користувачів.
  * Формування запитів на злиття (пропозиція додати нові музичні твори до оригінального списку відтворення).
* **Обмін повідомленнями:** Створення особистих бесід та групових чатів для текстового спілкування та обміну медіафайлами.
* **Синхронне прослуховування:** Можливість ініціювати сеанс синхронного мовлення у груповому чаті. Один користувач (ведучий) керує відтворенням музики, а інші учасники бесіди слухають її синхронно в режимі реального часу.

## 5. Аналіз помилок, що можуть виникнути

Під час експлуатації системи передбачена автоматична обробка виняткових ситуацій. Нижче наведено перелік типових помилок та шляхи їх вирішення:

1. **Помилка автентифікації або відмова у доступі:**
   * *Ознаки:* Система повертає користувача на сторінку входу або відображає сповіщення про відсутність прав (наприклад, при спробі змінити чужий список відтворення).
   * *Причина:* Завершення терміну дії сеансу (токена) або спроба виконати дію, яка не передбачена рівнем доступу поточного облікового запису.
   * *Рішення:* Повторно пройти процедуру авторизації; переконатися, що дія виконується над власними даними.

2. **Відхилення завантаження музичного твору (Конфлікт дублікатів):**
   * *Ознаки:* Під час завантаження аудіофайлу з'являється системне сповіщення про скасування операції.
   * *Причина:* Система розрахувала криптографічну суму (хеш) файлу і виявила, що абсолютно ідентичний файл вже існує в глобальному сховищі.
   * *Рішення:* Завантажити інший аудіозапис або перевірити власну бібліотеку на наявність цього твору.

3. **Відмова у формуванні запиту на злиття списків відтворення:**
   * *Ознаки:* При спробі інтегрувати свій список відтворення з оригіналом з'являється повідомлення про помилку протоколу.
   * *Причина:* Локальна копія списку відтворення не містить жодних нових композицій порівняно з оригіналом (відсутня "дельта" даних).
   * *Рішення:* Додати нові музичні твори до локальної копії перед формуванням запиту.

4. **Втрата синхронізації під час спільного прослуховування:**
   * *Ознаки:* Музика призупинилась, або на екрані з'явилося сповіщення про відключення від вузла мовлення.
   * *Причина:* Ведучий сеансу припинив мовлення, або відбулася короткочасна втрата з'єднання з сервером через нестабільність мережі.
   * *Рішення:* Зачекати на відновлення з'єднання та повторно натиснути кнопку приєднання до активного сеансу мовлення в чаті.

5. **Помилка завантаження зовнішніх медіафайлів (зображень чи аудіо):**
   * *Ознаки:* Замість обкладинки відображається стандартна піктограма, або музичний твір не відтворюється.
   * *Причина:* Компонент об'єктного сховища (MinIO) недоступний або пошкоджено тимчасове посилання доступу.
   * *Рішення:* Звернутися до адміністратора системи для перевірки стану контейнера зі сховищем об'єктів. Спробувати оновити сторінку застосунку.
